Maintainer tooling for the better-duck workspace. Not published.

cargo run -p xtask -- upgrade-duckdb --tag v1.5.5 regenerates crates/better-duck-sys/vendor/duckdb.tar.gz and crates/better-duck-sys/src/bindings.rs from a specific upstream duckdb/duckdb release tag — the only place a git checkout of DuckDB’s source ever touches this repo. The clone is ephemeral (a tempfile directory, deleted when this process exits, on any exit path); nothing is left behind as a submodule reference, and no consumer of better-duck-sys ever needs network access or Python to build it.

This calls into DuckDB’s own scripts/package_build.py (build_package(...)) to get the amalgamated (unity-build) source file list — the same officially-provided mechanism the community libduckdb-sys crate’s own update_sources.py uses — rather than reimplementing DuckDB’s internal source-selection logic in Rust, which would be fragile against upstream changes.
