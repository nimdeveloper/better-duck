better-duck is distributed on crates.io. Add `better-duck-core` for the driver, and
`better-duck-diesel` if you want the [Diesel ORM backend](/diesel/overview). DuckDB itself is
compiled and embedded — there is no system package to install.

<Warning>
  better-duck is a **pre-release** (`0.1.0-beta.8`). Cargo's default version requirement **excludes
  pre-release versions**: a requirement like `"0.1"` will *not* match `0.1.0-beta.8`. You must pin the
  exact version string, as shown below. See [Versioning & compatibility](/guide/versioning-and-compatibility).
</Warning>

## Add the crates

<Tabs>
  <Tab title="Cargo.toml">
    ```toml
    [dependencies]
    # DuckDB client (published on crates.io as `better-duck`)
    better-duck-core = "0.1.0-beta.8"

    # Optional: Diesel ORM backend
    better-duck-diesel = "0.1.0-beta.8"
    ```
  </Tab>
  <Tab title="cargo add">
    ```bash
    cargo add better-duck-core --version 0.1.0-beta.8
    # optional ORM backend
    cargo add better-duck-diesel --version 0.1.0-beta.8
    ```
  </Tab>
</Tabs>

<Note>
  `better-duck-macros` is pulled in automatically by the [`udf`](/guide/feature-flags) and
  [`derive`](/guide/feature-flags) features — you don't depend on it directly. Keep sibling crates on
  the **same** version.
</Note>

The default feature set is `["chrono", "decimal"]`. To pick features à la carte, see
[Feature flags](/guide/feature-flags).

## Bundled DuckDB — no system library

DuckDB is **compiled from vendored source and statically linked** into your binary by
`better-duck-sys`. You do **not** install a DuckDB system package, and there is no shared library to
ship at runtime. This is what makes better-duck [embedded-first](/guide/architecture#bundled-duckdb-embedded-first)
and suitable for Tauri desktop apps, iOS cross-builds, and other environments where a system library
isn't an option.

<Tip>
  Because DuckDB is compiled from source, your **first** build (and any clean rebuild) is slower than
  a typical crate — it is compiling the DuckDB engine itself. Subsequent incremental builds reuse the
  compiled artifact. Builds that bundle an [extension](/guide/extensions) (for example `json` +
  `parquet`) recompile a DuckDB variant and take noticeably longer.
</Tip>

## Toolchain requirements

<Info>
  The minimum supported Rust version (**MSRV**) is **1.96**. Check with `rustc --version`; update with
  `rustup update`. A C/C++ toolchain is also required to compile the vendored DuckDB (the one your
  platform already uses for native crates — e.g. the MSVC build tools on Windows, Xcode command-line
  tools on macOS, `gcc`/`clang` on Linux).
</Info>

## Troubleshooting

<AccordionGroup>
  <Accordion title="`cargo add better-duck-core` resolves to nothing / `0.1` doesn't match">
    Cargo excludes pre-releases from a default requirement. Pin the **exact** string
    `"0.1.0-beta.8"` (or pass `--version 0.1.0-beta.8` to `cargo add`).
  </Accordion>
  <Accordion title="The first build takes minutes">
    Expected — the first build compiles the DuckDB engine from source. Incremental builds reuse the
    artifact. Enabling an [extension feature](/guide/extensions) recompiles a variant and adds time.
  </Accordion>
  <Accordion title="A linker or C compiler error on first build">
    DuckDB is compiled from C/C++ source, so a working native toolchain is required. Install your
    platform's standard build tools (see [Toolchain requirements](#toolchain-requirements)) and rebuild.
  </Accordion>
  <Accordion title="Which DuckDB version am I running?">
    Call [`better_duck_core::library_version()`](/core/opening-connections#library-version) at runtime — it
    returns the linked DuckDB version string. There is no system DuckDB to match.
  </Accordion>
</AccordionGroup>
