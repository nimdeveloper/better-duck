better-duck is distributed on crates.io. Add `better-duck-core` for the driver, and
`better-duck-diesel` if you want the Diesel ORM backend.

<Warning>
  better-duck is currently a **pre-release** (`0.1.0-beta.8`). Cargo's default version requirement
  **excludes pre-release versions**: a requirement like `"0.1"` will *not* match `0.1.0-beta.8`. You
  must pin the exact version string, as shown below.
</Warning>

## Add the crates

<Tabs>
  <Tab title="Cargo.toml">
    ```toml
    [dependencies]
    # DuckDB client
    better-duck-core = "0.1.0-beta.8"

    # Optional: Diesel ORM backend
    better-duck-diesel = "0.1.0-beta.8"
    ```
  </Tab>
  <Tab title="cargo add">
    ```bash
    cargo add better-duck-core --version 0.1.0-beta.8
    # optional ORM backend
    cargo add better-duck-diesel --version 0.1.0-beta.8
    ```
  </Tab>
</Tabs>

<Note>
  `better-duck-macros` is pulled in automatically by the [`udf`](/guide/feature-flags) and
  [`derive`](/guide/feature-flags) feature flags — you don't depend on it directly.
</Note>

## Bundled DuckDB — no system library

DuckDB is **compiled from vendored source and embedded** into your binary by `better-duck-sys`. You
do **not** need to install a DuckDB system package, and there is no shared library to ship alongside
your application at runtime. This is what makes better-duck "embedded-first" and suitable for Tauri
desktop apps, iOS cross-builds, and other environments where a system library isn't an option.

<Tip>
  Because DuckDB is compiled from source, your **first** build (and any clean rebuild) is slower than
  a typical crate — it is compiling the DuckDB engine. Subsequent incremental builds reuse the
  compiled artifact. Builds that bundle an extension variant (for example the `json` + `parquet`
  features) recompile a DuckDB variant and can take noticeably longer.
</Tip>

## Toolchain requirements

<Info>
  The minimum supported Rust version (**MSRV**) is **1.96**. Make sure your toolchain is at least
  that version (`rustc --version`).
</Info>
