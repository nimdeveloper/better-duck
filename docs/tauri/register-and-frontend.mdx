This page covers wiring the plugin into your Tauri app and the full `@better-duck/tauri` frontend
API. For locking the surface down, see [security](/tauri/security); for choosing an engine, see
[backends & checkpoint](/tauri/backends-and-checkpoint).

## Install

Pick exactly **one** backend feature in `src-tauri/Cargo.toml`:

```toml
[dependencies]
# default backend-core:
better-duck-tauri = { version = "0.1.0-beta.8", features = ["backend-core"] }
# or the Diesel-native backend:
# better-duck-tauri = { version = "0.1.0-beta.8", default-features = false, features = ["backend-diesel"] }
# add Arrow IPC output:
# better-duck-tauri = { version = "0.1.0-beta.8", features = ["backend-core", "arrow"] }
```

<Warning>
Pre-release versions are excluded by Cargo's default version match — you **must** pin the exact
pre-release (`0.1.0-beta.8`), not `0.1.0`.
</Warning>

Frontend:

```bash
npm install @better-duck/tauri   # peer-depends on @tauri-apps/api ^2
```

The npm package name is `@better-duck/tauri`; the default export is the `Database` class.

## Register on `tauri::Builder`

<CodeGroup>
```rust Simple (defaults)
tauri::Builder::default()
    .plugin(better_duck_tauri::core::init())   // backend-core
    // .plugin(better_duck_tauri::diesel::init()) // backend-diesel
    .run(tauri::generate_context!())?;
```

```rust Configured (Builder)
use better_duck_tauri::{core::Builder, Migration, MigrationKind};

tauri::Builder::default()
    .plugin(
        Builder::new()
            .add_migrations("duckdb:app.db", migrations) // Vec<Migration> for core
            .read_only(false)
            .allow_connection("duckdb:app.db")
            .allow_path("/data")
            .deny_risky_statements(true)
            .allow_network(false)
            .checkpoint_interval(std::time::Duration::from_secs(300))
            .checkpoint_on_exit(true)
            .on_connect(|c| {
                my_udf::register(c)
                    .map_err(|e| better_duck_tauri::Error::Backend(e.to_string()))
            })
            .build(),
    )
    .run(tauri::generate_context!())?;
```
</CodeGroup>

The simple form uses defaults: a permissive `Policy` and passive checkpointing. Builder methods are
chainable and `#[must_use]`.

- `better_duck_tauri::core::Builder` / `core::init()` are gated behind `feature = "backend-core"`.
- `better_duck_tauri::diesel::Builder` / `diesel::init()` are gated behind `feature =
  "backend-diesel"`; the only builder difference is `add_migrations(conn_str, EmbeddedMigrations)`
  (from `embed_migrations!`) instead of a `Vec<Migration>`.
- `on_connect(hook: Fn(&mut Connection) -> Result<()>)` runs on every opened connection — register
  UDFs or `LOAD` extensions here. `Connection` is re-exported as `better_duck_tauri::Connection`.

<Tip>
`on_connect` is the right place to register [UDFs](/macros/udf) or `LOAD` extensions so
every opened connection carries them. On the Diesel backend the hook runs **once per physical
pooled connection** (re-registering a UDF on an already-initialized connection would fail) — see
[backends & checkpoint](/tauri/backends-and-checkpoint).
</Tip>

**Host-side re-exports:** `DuckBackend`, `Row`, `ExecuteResult`, `DataFormat`, `Migration`,
`MigrationKind`, `Policy`, `CheckpointConfig`, `EngineConfig`, `ConnectHook`, `Error`, `Result`, and
the `scope::Entry` schema type (`pub mod scope`).

## Grant permissions

Permissions live in a capability file (`src-tauri/capabilities/*.json`). The default set is
read-only:

```json
{
  "identifier": "duck-caps",
  "windows": ["main"],
  "permissions": [
    "better-duck-tauri:default",
    "better-duck-tauri:allow-execute",
    "better-duck-tauri:allow-import",
    "better-duck-tauri:allow-export"
  ]
}
```

- `better-duck-tauri:default` = `allow-load` + `allow-close` + `allow-select` (read only).
- `better-duck-tauri:allow-raw-sql` = `allow-select` + `allow-execute` (umbrella; **not** in default).
- Every command also has autogenerated `better-duck-tauri:allow-<command>` and `deny-<command>`
  permissions. The identifiers hyphenate underscores: `allow-load`, `allow-close`, `allow-select`,
  `allow-execute`, `allow-load-extension`, `allow-import`, `allow-export`, `allow-append-rows`,
  `allow-tables`, `allow-columns`, `allow-explain`, `allow-stream`, `allow-checkpoint`,
  `allow-interrupt`, `allow-revert`, `allow-query-arrow`.

See [security](/tauri/security) for scope `connection`/`path` constraints and the `Policy`.

## The `Database` frontend class

```ts
import Database from '@better-duck/tauri'

const db = await Database.load('duckdb:analytics.db') // or 'duckdb::memory:'
```

`db.path` holds the connection string the handle was loaded with; it is passed as `db` to every
command. Methods bind parameters positionally as `$1, $2, …`:

```ts
// reads / writes
const rows = await db.select<{ id: number }>('SELECT id FROM t WHERE id > $1', [10])
const res  = await db.execute('INSERT INTO t VALUES ($1, $2)', [1, 'a']) // { rowsAffected }

// analytics
await db.loadExtension('spatial')
await db.importParquet('sales', 'data/2026-*.parquet') // import(table, src, 'parquet')
await db.importCsv('t', 'in.csv'); await db.importJson('t', 'in.json')
await db.exportParquet('SELECT * FROM sales', 'out.parquet')
await db.exportCsv('SELECT * FROM sales', 'out.csv')
await db.appendRows('events', [{ id: 1, kind: 'click' }]) // columns from the first row; missing keys → NULL

// introspection + maintenance
await db.tables(); await db.columns('sales'); await db.explain('SELECT * FROM sales')
await db.checkpoint(true)   // FORCE CHECKPOINT
await db.revert()           // undo the last migration → version | null

// streaming + cancellation
const total = await db.stream('SELECT * FROM huge', rows => render(rows), [], 1000)
await db.interrupt()        // cancel an in-flight stream → bool
```

`import`/`export` take a `DataFormat` of `'parquet' | 'csv' | 'json'`; the `importParquet` /
`exportCsv` / etc. helpers are thin wrappers. `appendRows` takes column order from the **first
row's** keys and binds keys missing from later rows as `NULL`. `tables`/`columns` query
`information_schema` (`columns` returns `column_name`, `data_type`, `is_nullable`).

### Streaming

`stream(query, onBatch, values?, chunk?)` opens a Tauri `Channel`, delivers each batch of up to
`chunk` rows (default **1024**) to `onBatch`, and resolves to the total row count. `interrupt()`
cancels the single in-flight stream registered for that connection and returns whether one was
signalled.

<Note>
Only one stream is tracked per connection. `interrupt()` cancels that in-flight stream; it returns
`false` if nothing was running.
</Note>

## Arrow IPC (feature `arrow`)

With the plugin's `arrow` Cargo feature, `db.queryArrow(sql, values?)` returns an `ArrayBuffer` of
Arrow IPC **stream** bytes:

```ts
import { tableFromIPC } from 'apache-arrow'
const buf = await db.queryArrow('SELECT * FROM sales')
const table = tableFromIPC(new Uint8Array(buf))
```

Server-side this calls better-duck-core's Arrow C Data Interface export and serializes it with
arrow-rs `StreamWriter`, returning the raw IPC body via `tauri::ipc::Response`.

<Warning>
Without the `arrow` feature, the `query_arrow` command returns a backend error ("the `arrow` feature
is not enabled").
</Warning>

## JSON value mapping

<Tabs>
<Tab title="Params (JS → DuckDB)">
Positional, from the `values` array:

| JS value | DuckDB type |
|---|---|
| `null` | NULL |
| boolean | BOOLEAN |
| integer | BIGINT (unsigned → UBIGINT, otherwise DOUBLE) |
| string | VARCHAR |
| array | LIST |
| object | STRUCT |
</Tab>
<Tab title="Results (DuckDB → JS)">
| DuckDB type | JS value |
|---|---|
| integers / floats | number |
| `HUGEINT` / `UHUGEINT` / `DECIMAL` / `UUID` / `BIT` / `BIGNUM` | **string** (survives JS `number` limits) |
| `BLOB` | array of byte values |
| `LIST` / `ARRAY` / `STRUCT` / `MAP` / `UNION` / `ENUM` | structured JSON |
| dates / times / timestamps | ISO-8601 string |

See the [DuckDB types](/guide/duckdb-essentials) reference for the full type system.
</Tab>
</Tabs>
