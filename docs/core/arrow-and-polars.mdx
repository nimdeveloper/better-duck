---
title: "Arrow & Polars interop"
description: "Export via the Arrow C Data Interface with zero added dependencies, and round-trip DataFrames with Polars."
---

Two feature-gated bridges for handing DuckDB results to the Arrow ecosystem, both built on the
**Arrow C Data Interface**.

## Arrow (feature `arrow`)

<Info>Requires `feature = "arrow"` — **no Arrow library is pulled in**; the crate defines the ABI
structs directly.</Info>

On `Connection`:

- `query_arrow(sql, binds) -> Result<ArrowResult>` — run SQL and export the result. `binds` is the
  same `&mut [&mut dyn AppendAble]` as [`execute_with`](/core/parameters-and-prepared).
- `register_arrow(view_name, stream)` (`unsafe`) — register a caller-owned `ArrowArrayStream`
  pointer as a queryable DuckDB view; returns an `ArrowView` guard that drops the view when it falls
  out of scope.

```rust
let arrow = conn.query_arrow("SELECT 1 AS a, 2 AS b UNION ALL SELECT 3, 4", &mut [])?;
let cols = arrow.schema().n_children();     // 2
let rows = arrow.row_count();               // 2
```

`ArrowResult` yields `schema() -> &ArrowSchemaHandle`, `arrays() -> &[ArrowArrayHandle]`,
`row_count()`, and `into_parts()`. A consumer with `arrow-rs` reinterprets the handles' `as_ptr()`
/ `as_mut_ptr()` (or `export_to`) as `FFI_ArrowSchema` / `FFI_ArrowArray` — the layout is
identical. Handles call their `release` callback on drop.

<Warning>
  **`register_arrow` safety:** the stream must stay valid and untouched until the returned
  `ArrowView` guard drops.
</Warning>

## Polars (feature `polars`)

<Info>Requires `feature = "polars"`, which implies `arrow`. Bridges via the Arrow C Data Interface
(`polars` + `polars-arrow`, no `arrow-rs`).</Info>

On `Connection`:

- `query_polars(sql, binds) -> Result<polars::prelude::DataFrame>` — run SQL and collect the result
  into a `DataFrame`.
- `register_polars(name, &DataFrame) -> Result<()>` — materialize a `DataFrame` into DuckDB as a
  real table named `name` (`CREATE OR REPLACE TABLE … AS SELECT`), so the `DataFrame` need not
  outlive the call.

```rust
let df = conn.query_polars("SELECT id, name FROM t ORDER BY id", &mut [])?;
conn.register_polars("dst", &df)?;         // round-trip back into DuckDB
```
