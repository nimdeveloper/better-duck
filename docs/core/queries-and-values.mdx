Everything runs through a [`Connection`](/core/connections) (`&mut self` for SQL). A query returns
a `DuckResult` that is both a lazy row iterator and a carrier of result metadata. A column value is
a `DuckValue`, and rows come out as `DuckRow`.

## Executing statements

Each executor is `#[must_use]`.

```rust
// Multiple ';'-separated statements; results discarded. DuckDB splits (NUL-safe,
// comment/dollar-quote aware) — not a Rust-side split. Use for DDL and simple DML.
conn.execute_batch("CREATE TABLE t (id INTEGER, name VARCHAR); INSERT INTO t VALUES (1, 'a')")?;

// Prepare + execute ONE statement, returning a DuckResult.
let mut result = conn.execute("SELECT id, name FROM t")?;
```

`execute` works for every statement kind:

- **SELECT / RETURNING** → iterate rows (the `Iterator` impl).
- **INSERT / UPDATE / DELETE** → `result.changes()` is the affected-row count.
- **DDL** → `changes()` is `0`, with no rows.

`conn.extract_statements(sql)` parses a multi-statement string into an `ExtractedStatements` batch
whose statements you `prepare(i)` and run individually — see
[Parameters & Prepared Statements](/core/parameters-and-prepared).

## Iterating a DuckResult

`DuckResult` owns the DuckDB result and is an `Iterator<Item = Result<DuckRow>>`. Plain forward
iteration decodes each row once and caches nothing.

```rust
for row in conn.execute("SELECT id, name FROM t ORDER BY id")? {
    let row = row?;                     // Result<DuckRow>
    // ... use row ...
}

// Or drive it manually:
let mut result = conn.execute("SELECT id FROM t")?;
while let Some(row) = result.next() {
    let row = row?;
}
```

Row-oriented helpers:

- `next()` — the `Iterator` method.
- `exists() -> Result<bool>` — peek whether at least one more row exists **without consuming it**;
  a later `next()` still yields that row. Idempotent.
- `count() -> usize` — consumes the result and tallies remaining rows **without** materializing
  each `DuckRow` (skips per-column conversion). Spans multiple internal chunks correctly.
- `materialize() -> Result<ResultSet>` — see [below](#materializing-to-a-resultset).
- `enable_rewind()` then later `rewind()` — an opt-in replay cache. Call `enable_rewind()`
  *before* consuming the rows you want to replay; without it `rewind()` is a no-op.

<Warning>
  **Row vs chunk — do not mix.** A `DuckResult` is consumed **either** row-by-row
  (`next` / `exists` / `count` / `materialize`) **or** chunk-by-chunk (`fetch_chunk`, feature
  `columnar`), never both. Calling one mode after the other yields `Error::MixedIterationMode`.
  See [columnar access](/core/columnar).
</Warning>

## DuckRow access

A `DuckRow` is one row's values plus shared column names.

- `get(name: &str) -> Option<&DuckValue>` — by column name, **case-sensitive**, matched by string
  (returns the first match if names repeat).
- `get_idx(idx: usize) -> Option<&DuckValue>` — by zero-based index.
- `column_count() -> u64`.

```rust
use better_duck_core::types::value::DuckValue;

let mut result = conn.execute("SELECT id, name FROM t")?;
let row = result.next().unwrap()?;
match row.get("name") {
    Some(DuckValue::Text(s)) => println!("{s}"),
    Some(DuckValue::Null) => println!("<null>"),
    _ => {}
}
```

## Materializing to a ResultSet

`DuckResult::materialize()` consumes the result and returns a `ResultSet`
(`better_duck_core::ResultSet`) that holds **no FFI handles** — it is `Send + Sync + Clone`, so it
can cross threads (e.g. out of a `spawn_blocking` closure; the [async facade](/core/async-and-pooling)
returns one).

```rust
let set = conn.execute("SELECT id, name FROM t ORDER BY id")?.materialize()?;
assert!(!set.is_empty());
for row in set.rows() {              // &[DuckRow]
    let _ = row.get("id");
}
let first = set.first();             // Option<&DuckRow>
let n = set.len();
let changed = set.changes();         // affected-row count for DML; 0 for SELECT

// ResultSet is Send + Sync + Clone — move it to another thread.
let moved = set.clone();
let counted = std::thread::spawn(move || moved.len()).join().unwrap();
```

`ResultSet` also exposes `into_rows()`, `column_names()`, `column_schema()`, `statement_type()`,
`result_type()`, and implements `IntoIterator`. With the `derive` feature and a
`#[derive(FromRow)]` type, `set.to_structs::<T>()` reads the whole result into `Vec<T>` — see
[data derives](/macros/derives).

## The DuckValue type

`better_duck_core::types::value::DuckValue` is `#[non_exhaustive]` — always include a `_` arm. It
is `Clone + PartialEq + Eq + Hash` (floats canonicalized, maps hashed order-independently), so it
works as a `HashMap` key. Constructors/helpers: `DuckValue::text(impl Into<String>)`, and on a
`Map` variant `get` / `get_mut` / `contains_key`. `Option<T>` converts to `Null` / `Some`.

| DuckDB type | `DuckValue` variant | Inner Rust type |
|---|---|---|
| NULL | `Null` | — |
| BOOLEAN | `Boolean` | `bool` |
| TINYINT / SMALLINT / INTEGER / BIGINT | `TinyInt` / `SmallInt` / `Int` / `BigInt` | `i8` / `i16` / `i32` / `i64` |
| HUGEINT | `HugeInt` | `i128` |
| UTINYINT / USMALLINT / UINTEGER / UBIGINT | `UTinyInt` / `USmallInt` / `UInt` / `UBigInt` | `u8` / `u16` / `u32` / `u64` |
| UHUGEINT | `UHugeInt` | `u128` |
| FLOAT / DOUBLE | `Float` / `Double` | `f32` / `f64` |
| TIMESTAMP | `Timestamp` | `chrono::NaiveDateTime` *(chrono)* / `std::time::SystemTime` |
| TIMESTAMP_S / _MS / _NS | `TimestampS` / `TimestampMs` / `TimestampNs` | as `Timestamp` |
| TIMESTAMPTZ | `TimestampTz` | `chrono::DateTime<Utc>` *(chrono)* / `SystemTime` |
| DATE | `Date` | `chrono::NaiveDate` *(chrono)* / `types::date_native::DuckDate` |
| TIME | `Time` | `chrono::NaiveTime` *(chrono)* / `DuckTime` |
| TIME_NS | `TimeNs` | `chrono::NaiveTime` *(chrono)* / `DuckTimeNs` |
| TIME_TZ | `TimeTz` | `types::date_chrono::TimeTz` *(chrono)* / `date_native::DuckTimeTz` |
| INTERVAL | `Interval` | `chrono::Duration` *(chrono)* / `std::time::Duration` |
| DATE/TIMESTAMP ±infinity | `TemporalInfinity { kind: TemporalKind, sign: Sign }` | feature-independent sentinel |
| VARCHAR | `Text` | `String` |
| DECIMAL(w,s) | `Decimal` | `types::decimal::DuckDecimal` (width+scale preserved) |
| BLOB *(and GEOMETRY WKB)* | `Blob` | `types::blob::Blob` (wraps `Vec<u8>`) |
| LIST | `List` | `Vec<DuckValue>` |
| ARRAY | `Array` | `Box<[DuckValue]>` |
| STRUCT | `Struct` | `HashMap<String, DuckValue>` |
| MAP | `Map` | `HashMap<DuckValue, DuckValue>` |
| UNION | `Union` | `types::duck_union::DuckUnion` |
| ENUM | `Enum` | `types::duck_enum::DuckEnum` (dictionary + index) |
| UUID | `Uuid` | `types::uuid::DuckUuid` |
| BIT | `Bit` | `types::bit::DuckBit` |
| BIGNUM | `Bignum` | `types::bignum::DuckBignum` |

<Info>
  A column that read-support does not yet cover (e.g. GEOMETRY value accessors) surfaces as a
  `DuckDBConversionError`. `GEOMETRY` physically arrives as its WKB `Blob`.
</Info>

The inner temporal type depends on the `chrono` feature (default on). Without it you get the native
`DuckDate` / `DuckTime` / `SystemTime` types — see [feature flags](/guide/feature-flags).

## Result & column metadata

On a `DuckResult` (and, where noted, `ResultSet`):

- `changes() -> u64`, `column_count() -> u64`.
- `column_name(idx) -> Result<&str>`, `column_names() -> &[Box<str>]`,
  `column_idx(name) -> Option<usize>`.
- `column_type(idx) -> Result<DUCKDB_TYPE>` — the coarse DuckDB type id (kept for migration).
- `column_logical_type(idx) -> Result<&TypeInfo>` / `column_schema() -> &[TypeInfo]` — the
  **lossless** descriptor: DECIMAL width/scale, nested LIST/STRUCT/MAP shapes, ENUM labels.
  `TypeInfo` is `better_duck_core::types::TypeInfo` (e.g. `TypeInfo::Decimal { width, scale }`,
  `TypeInfo::List(..)`, `TypeInfo::Scalar(id)`).
- `statement_type() -> StatementType`, `result_type() -> ResultType`
  (`QueryResult` / `ChangedRows` / `Nothing` / `Invalid` / `Unknown`, `#[non_exhaustive]`).

```rust
let select = conn.execute("SELECT 1 AS a, 'x' AS b, 3.5 AS c")?;
assert_eq!(select.column_count(), 3);
assert_eq!(select.column_name(1)?, "b");
assert_eq!(select.column_idx("c"), Some(2));
let _schema = select.column_schema();         // &[TypeInfo]
```

Column metadata is available **before** consuming any rows. An out-of-range index yields
`Error::InvalidColumnIndex`.

## TableDescription

Read a catalog table's columns **without issuing a query** — `better_duck_core::TableDescription`,
created from a `Connection` (`&self`):

```rust
let desc = conn.table_description("main", "t")?;          // (schema, table), default catalog
// or: conn.table_description_ext(Some("memory"), "main", "t")?;  // explicit catalog (None = default)

let n = desc.column_count();                               // u64 — the trusted bound
for i in 0..n {
    let name: Option<String> = desc.column_name(i);
    let ty = desc.column_type(i);                          // Option<TypeInfo> (lossless)
    let has_default: bool = desc.column_has_default(i)?;   // Err on a bad index
}
```

`error() -> Option<String>` carries DuckDB's catalog-aware message. A missing table or an interior
NUL in a name is an error at creation. Indexed accessors return `None` out of range (except
`column_has_default`, which errors).

<Warning>
  `conn.table_names(sql, qualified) -> Result<Vec<String>>` reports the tables a query reads
  (DuckDB's own parser) — but the SQL **must be syntactically valid**, or an upstream C-API defect
  aborts the process. Only pass SQL you know parses.
</Warning>
