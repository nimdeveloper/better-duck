DuckDB has **no** dedicated transaction entry point in its C API, so `better-duck-core` drives
transactions with plain SQL (`BEGIN TRANSACTION` / `COMMIT` / `ROLLBACK`) through
[`execute_batch`](/core/executing-sql#execute_batch-fire-and-forget). Three ergonomic styles are
offered on [`Connection`](/core/opening-connections), each a different trade-off.

## Closure scope (recommended)

`transaction<T, F: FnOnce(&mut Connection) -> Result<T>>(&mut self, f) -> Result<T>` runs a closure
inside a transaction: `BEGIN`, then `COMMIT` on `Ok` or `ROLLBACK` on `Err`.

```rust
conn.transaction(|c| {
    c.execute_batch("INSERT INTO t VALUES (1)")?;
    c.execute_with("INSERT INTO t VALUES ($1)", &mut [&mut 2_i32])?;
    Ok(())                           // returning Err here rolls everything back
})?;
```

The original error is preserved — a rollback failure never masks it.

## RAII guard

`begin_transaction(&mut self) -> Result<Transaction<'_>>` returns a `better_duck_core::Transaction`
guard that **derefs to the `Connection`** and rolls back on drop unless committed. This is what
makes the `?`-early-return path safe without a closure.

```rust
let mut tx = conn.begin_transaction()?;
tx.execute_batch("INSERT INTO t VALUES (1)")?;   // runs through Deref to Connection
tx.commit()?;                                     // or tx.rollback()?; or just drop to roll back
```

- `commit(self) -> Result<()>` and `rollback(self) -> Result<()>` consume the guard.
- Dropping the guard without either does a best-effort rollback.

## Low-level verbs

`begin()`, `commit()`, and `rollback()` on `Connection` issue the raw statements directly when you
need manual control.

<Warning>
  A transaction must **not** span an `.await` point. On the [async facade](/core/async) run the
  whole unit inside `with_connection` (or `AsyncPool::with`) so `BEGIN`/`COMMIT` stay on one
  blocking dispatch. See [async transactions](/core/async#running-a-transaction).
</Warning>

## The `transaction!` macro

With the `derive` feature, `transaction!(conn, { … })` is a terser scope that commits on `Ok` and
rolls back on `Err` or panic. It works for both the core `Connection` and a Diesel
`DuckDbConnection` (both expose `transaction(|c| -> Result<_>)`):

```rust
use better_duck_core::transaction;

transaction!(conn, {
    conn.execute_batch("INSERT INTO t VALUES (1)")?;
    Ok(())
})?;
```

See [helper macros](/macros/helper-macros#transaction).

## No savepoints

<Note>
  DuckDB supports only `BEGIN` / `COMMIT` / `ROLLBACK` / `ABORT` — **not** `SAVEPOINT` / `RELEASE`
  / `ROLLBACK TO`. There is deliberately no savepoint API.
</Note>
