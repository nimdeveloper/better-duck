## The `#[duck(...)]` attributes

`FromRow`, `ToRow`, and `DuckStruct` share the `#[duck(...)]` attribute:

- **Container**: `#[duck(rename_all = "…")]`, `#[duck(crate = ::path)]`.
- **Field**: `#[duck(rename = "column")]`.

`DuckEnum` uses a **separate** `#[duck_enum(...)]` attribute with the same `rename` / `rename_all` /
`crate` options (so an enum can derive both `DuckEnum` and other `#[duck]`-based traits without
clashing).

The `crate = ::path` option retargets the generated `::better_duck_core` path — useful for crates
that re-export the library under another name.

## `rename_all` casings

`rename_all` accepts these casing names. Names are split into words on `_` / `-` **and** at
lower→Upper boundaries, so both snake-case fields and Pascal/camel variants map correctly (a run of
uppercase letters counts as one word, e.g. `HTTPServer` → `httpserver` under snake_case):

| `rename_all` value | `userName` → |
|---|---|
| `"lowercase"` | `username` |
| `"UPPERCASE"` | `USERNAME` |
| `"snake_case"` | `user_name` |
| `"SCREAMING_SNAKE_CASE"` | `USER_NAME` |
| `"kebab-case"` | `user-name` |
| `"SCREAMING-KEBAB-CASE"` | `USER-NAME` |
| `"camelCase"` | `userName` |
| `"PascalCase"` | `UserName` |

**Resolution order** for a field/variant name: explicit `rename` → container `rename_all` → the Rust
identifier verbatim.
