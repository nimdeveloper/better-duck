<Info>
  These derives and helper macros come from `better-duck-core`'s `feature = "derive"`. Import them
  from `better_duck_core::…` — you never depend on `better-duck-macros` directly.
</Info>

Four derives map plain Rust types to DuckDB rows, `STRUCT`s, and `ENUM`s, and two helper macros
smooth out transactions and parameter binding.

## `#[derive(FromRow)]` — read a struct from a query row

Generates `better_duck_core::FromRow`: each **named** field is read from the row by column name via
`FromDuckValue`. [`ResultSet::to_structs::<T>()`](/core/queries-and-values#materializing-to-a-resultset)
collects a whole result into `Vec<T>`.

```rust
use better_duck_core::FromRow;

#[derive(FromRow, Debug)]
#[duck(rename_all = "snake_case")]
struct Task {
    user_id: i32,
    #[duck(rename = "n")]
    name: String,
    done: Option<bool>,   // NULL → None; a NULL into a non-Option field is an error
}

# fn demo(conn: &mut better_duck_core::connection::Connection) -> better_duck_core::error::Result<()> {
let tasks: Vec<Task> = conn.execute("SELECT user_id, n, done FROM tasks")?.materialize()?.to_structs()?;
# Ok(())
# }
```

- Container attributes: `#[duck(rename_all = "…")]`, `#[duck(crate = ::path)]`.
- Field attribute: `#[duck(rename = "column")]`.
- Named-field structs only; tuple structs and enums are rejected.

## `#[derive(ToRow)]` — write a struct as a row / params

Generates `better_duck_core::AppendAble`, appending/binding each field in **declaration order** —
one bulk-[appender](/core/appender) row, or consecutive `$1`, `$2`, … statement parameters.

```rust
use better_duck_core::ToRow;

#[derive(ToRow)]
struct NewItem { id: i32, name: String }

# fn demo(conn: &mut better_duck_core::connection::Connection) -> better_duck_core::error::Result<()> {
let mut app = conn.appender("items", "main")?;
app.append(&mut NewItem { id: 1, name: "a".to_owned() })?;
app.save()?;
# Ok(())
# }
```

Only the container `#[duck(crate = ::path)]` is honored (there is no column-name mapping — fields
bind positionally).

## `#[derive(DuckEnum)]` — a Rust unit enum ↔ DuckDB `ENUM`

Generates `From<T> for DuckValue`, `FromDuckValue for T`, and `AppendAble for T` (bound by label,
which DuckDB casts to the target `ENUM`). Variants must be **unit** variants; at least one is
required.

```rust
use better_duck_core::DuckEnum;

#[derive(DuckEnum, Debug, PartialEq, Clone, Copy)]
#[duck_enum(rename_all = "snake_case")]
enum Priority {
    Low,
    #[duck_enum(rename = "HIGH")]
    High,
}
```

- Container attributes: `#[duck_enum(rename_all = "…")]`, `#[duck_enum(crate = ::path)]`.
- Variant attribute: `#[duck_enum(rename = "label")]`.
- Reads accept either an `ENUM` value or a `VARCHAR` label.

<Note>
  `#[derive(DuckEnum)]` (the macro, attribute `#[duck_enum(...)]`) is distinct from the runtime
  `better_duck_core::types::DuckEnum` value type it maps through.
</Note>

## `#[derive(DuckStruct)]` — a Rust struct ↔ DuckDB `STRUCT`

Generates `From<T> for DuckValue` and `FromDuckValue for T` for a named-field struct, mapping it to
a DuckDB `STRUCT` value (named fields, fixed schema). It shares the **same** `#[duck(rename = "…")]`
/ `#[duck(rename_all = "…")]` / `#[duck(crate = …)]` attributes as `#[derive(FromRow)]`.

## `rename_all` casings

Accepted by `#[duck(rename_all = …)]` and `#[duck_enum(rename_all = …)]`. Names are split into
words on `_` / `-` and at lower→Upper boundaries, so both snake-case fields and Pascal/camel
variants map correctly:

`"lowercase"`, `"UPPERCASE"`, `"snake_case"`, `"SCREAMING_SNAKE_CASE"`, `"kebab-case"`,
`"SCREAMING-KEBAB-CASE"`, `"camelCase"`, `"PascalCase"`.

Resolution order for a field/variant name: explicit `rename` → container `rename_all` → the Rust
identifier verbatim.

## Diesel emission (better-duck-diesel `feature = "derive"`)

With better-duck-diesel's `derive` feature on, `#[derive(DuckEnum)]` and `#[derive(DuckStruct)]`
additionally emit Diesel `ToSql` / `FromSql` against `better_duck_diesel::sql_types::DuckEnum` /
`DuckStruct` (via `sql_query` + `QueryableByName`), so the same type binds and loads through a
`DuckDbConnection`. The deriving crate must then depend on `better-duck-diesel` — see the
[Diesel docs](/diesel).

## Helper macros

**`transaction!(conn, { … })`** — a scope that commits on `Ok` and rolls back on `Err` or panic. It
works for both the core [`Connection`](/core/transactions) and a Diesel `DuckDbConnection`, since
both expose `transaction(|c| -> Result<_>)`.

**`params![a, b, …]`** — builds the `&mut [&mut dyn AppendAble]` slice for
[`execute_with`](/core/parameters-and-prepared) without the boilerplate; mix in literals, owned
values, and `Null`.

```rust
use better_duck_core::{params, transaction};

# fn demo(conn: &mut better_duck_core::connection::Connection) -> better_duck_core::error::Result<()> {
transaction!(conn, {
    conn.execute_with("INSERT INTO t VALUES ($1, $2)", &mut params![1_i32, "hi".to_owned()])?;
    Ok(())
})?;
# Ok(())
# }
```
